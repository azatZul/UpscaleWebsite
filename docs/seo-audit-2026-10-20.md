# Технический аудит upscales.app — 20 октября 2026

Проверена публичная версия сайта HTTP-запросами, исходный HTML, первый экран в браузере и код текущего рабочего каталога. Сайт и настройки публикации не изменялись.

## Вывод

Общего технического запрета на индексацию основных страниц не обнаружено. Все 113 URL из публичного sitemap доступны и разрешают индексацию. Основное ограничение: браузерный инструмент `/upscale/` и все его языковые версии явно закрыты через `noindex`. Это соответствует комментарию в коде о preview, но мешает продвижению инструмента в поиске, если он уже готов к запуску.

## Что исправить

### 1. Открыть инструмент для поиска, когда preview завершён — высокий приоритет для SEO инструмента

Публичный `https://upscales.app/upscale/` и шесть переводов возвращают одновременно:

```text
HTML: <meta name="robots" content="noindex,follow">
HTTP: X-Robots-Tag: noindex, nofollow
```

Инструмента нет в sitemap. Разрешение в robots.txt не отменяет `noindex`. Google документирует удаление страницы из поиска при обнаружении этой директивы: [Block Search indexing with noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

Места в коде:

- `build/build.py:1883` — комментарий о preview.
- `build/build.py:1926` — meta robots инструмента.
- `static/_headers:22` и `static/_headers:28` — HTTP-заголовки инструмента и переводов.
- `build/build.py:2109` — генерация sitemap без инструмента.

Когда инструмент готов к органическому трафику: убрать оба источника запрета, убрать `nofollow` с публичной страницы инструмента и добавить семь канонических URL с hreflang в sitemap. Личный кабинет, персональную историю и приватные результаты оставить закрытыми. До завершения preview текущая настройка оправданна.

### 2. Добавить постоянный HTTP → HTTPS редирект — средний приоритет

Отдельный запрос без следования редиректам к `http://upscales.app/` возвращает **200 OK**, а не 301/308. Страница содержит HTTPS canonical, что уже помогает выбрать основной URL, но сервер продолжает выдавать копию по HTTP.

Рекомендуется перенаправлять HTTP на HTTPS с сохранением пути и query. Справка Google: [каноникализация дублирующихся URL](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).

Это не означает, что основная HTTPS-версия не индексируется. Браузерное повышение до HTTPS для домена `.app` также не заменяет серверный редирект для HTTP-клиентов.

### 3. Уточнить обещание о приватности — средний приоритет для доверия

На публичных страницах баннер содержит фразу “Your photos are never sent or tracked.” Русский вариант: «Ваши фото никуда не отправляются и не отслеживаются».

При этом [Privacy Policy](https://upscales.app/privacy_policy.html) описывает отправку выбранных фото для облачной обработки; в облачных инструментах сайта фото и результаты хранятся в истории до удаления пользователем. Баннер слишком категоричен для всех режимов.

Источник: `localization/common.json:495`, блок `consent.body`, семь переводов. Уточнить и комментарий к этому блоку, который сейчас предполагает только локальную обработку.

Пример смысла новой формулировки: «Локальные инструменты обрабатывают фото на вашем устройстве. Облачные режимы отправляют только выбранные вами фото; условия хранения описаны в политике конфиденциальности». Это несоответствие текста, а не обнаруженная причина блокировки индексации.

### 4. Настроить адрес с www — низкий приоритет

Для `https://www.upscales.app/` DNS-имя не разрешилось из среды проверки. Основной `upscales.app` работает. Желательно настроить DNS, TLS и постоянный редирект `www` → основной домен, сохраняя путь и query. Это полезно для посетителей и внешних ссылок с `www`; наличие `www` не обязательно для индексации основного домена.

### 5. Доработать альтернативные URL и страницу ошибки — низкий приоритет

- `/compare` и `/compare/` возвращают 404; `/compare.html` работает и используется сайтом. Можно добавить 301 на `.html` для удобства и защиты внешних ссылок от опечаток. Внутренних ссылок на эти 404 не обнаружено.
- `/index.html`, `/ru/index.html`, `/guides/index.html` возвращают 200 с корректным canonical на соответствующий каталог. Редиректы могли бы убрать доступные дубли, но canonical уже настроен; это не критическая ошибка.
- Проверенные 404 имеют пустое тело. Код статуса правильный для поиска; посетителям полезна собственная страница с навигацией.

### 6. Измерять переходы в магазины — улучшение аналитики

На кнопках магазинов есть `data-cta`, но в проверенном коде маркетинговых страниц не найден обработчик отправки событий переходов. На публичной главной из внешних скриптов подключён только `assets/site.js`. Amplitude подключается в модуле браузерного инструмента.

Если нужно оценивать конверсию сайта, добавить события перехода в App Store / Google Play после согласия на аналитику: магазин, страница, язык, позиция кнопки. Сам переход на страницу магазина не подтверждает установку приложения.

- Индивидуальные альбомы уже закрыты от поисковой индексации. Это не ограничивает доступ по ссылке и не подтверждает наличие или отсутствие согласий на публикацию.
- Рейтинг 4,6 и 1 648 оценок задан статически в `build/app_facts.json`, без даты и географии. Его актуальность и источник в этом аудите не подтверждены. Полезно добавить источник, регион или worldwide и дату обновления.

## Что нельзя заключить по этому аудиту

HTTP 200 и отсутствие запретов означают техническую возможность индексации, но не подтверждают фактическое присутствие всех страниц в Google или Яндексе. Нужны отчёты Google Search Console и Яндекс Вебмастера: индексирование страниц, выбранные поисковиком canonical, обработка sitemap, обход и ограничения безопасности. Пустой результат отдельного запроса `site:` также не является доказательством отсутствия сайта в индексе.

Core Web Vitals, Lighthouse и мобильная скорость здесь не измерялись. Проверка 206 ресурсов касается только ссылок CSS/JS/изображений в HTML страниц sitemap, без полного графа импортов, видео и исполнения всех сценариев приложения. Разбор JSON-LD подтверждает синтаксис, но не прохождение Rich Results Test или право на расширенные результаты.
